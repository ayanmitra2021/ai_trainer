MASTERY PULSE — SYSTEM OVERVIEW
INTERNAL BUILD · SOLO-MAINTAINED

Mastery
Pulse.

Certification prep and adoption tracking usually live in two disconnected systems: a learning tool that measures whether you knew something on a quiz, and an analytics tool that measures whether you're using anything at all. Neither one tells a practice lead if training actually changed real work.

Mastery Pulse is one application built from two ideas sharing a single skill graph — a closed loop between what someone has learned and what they actually do.

12 agents 3 workflows 4 cert providers Postgres + pgvector FastAPI · React
Adoption gaps feed the Curriculum Planner's next recommendation — the loop that gives the product its name.
ARCHITECTURE

Twelve agents. Three workflows. No framework.

Each agent is a single-purpose, typed unit — one input contract, one Structured-Output contract, one audited run. Plain async Python sequences them; nothing is hidden inside a graph a human has to reconstruct at 2am.

recommend_certification

The front door for a new practitioner — a 4-question intake.

generate_learning_path

Sync chain, then two independent background tasks — the HTTP response returns before either finishes.

nudge_campaign

Admin-initiated, on demand — never scheduled, never sees raw PII in the LLM step.

Provider resilience — 3-tier fallback chain (NVIDIA-primary mode)

Circuit breaker: 5 consecutive both-tier NVIDIA failures → 2-min cooldown, routes straight to Haiku. Max wall time if all fail: 50s.
TRUST & ACCESS

Three identities, one cookie, a privacy floor that's structural.

No JWT, no external identity provider. Access boundaries are enforced server-side — a client that bypasses the frontend gets the same answer as anyone else.

Identity scope

Deactivation → force logout, in one transaction

The cookie is a lookup key, not a self-contained credential — deleting the row makes it permanently worthless. No client-side reconstruction is possible.

Organization & plan hierarchy (multi-tenant layer)

Plan limits resolve at request time via a live join — a product-admin upgrade takes effect on the next API call, no data migration.
OVERSIGHT & STATUS

Claude Code owns the plumbing. The judgment calls are owned directly.

Not "write the Python yourself" — "own the prompt file, the rubric, or the policy decision." Roughly a dozen points across the build are flagged for that reason.
